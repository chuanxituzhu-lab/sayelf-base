## 附录：关键总结

| 维度 | 结论 |
|------|------|
| **Skill 元数据** | 行业事实标准已形成，name + description 通用 |
| **Skill 正文** | 框架间有差异，但"概述→步骤→约束"三层结构通用 |
| **Agent 模板** | 无统一标准，推荐"YAML 元数据 + 角色 + 九大板块"或 AGENTS.md |
| **评测集** | JSON 格式 + 四类场景覆盖 + 双轨评分是最佳实践 |
| **FDE 定义** | 三要素（生产工程 + 现场问题发现 + 产品反馈） |
| **FDE 组织** | Echo-Delta 双人单元，2-6 人 Pod |
| **FDE 流程** | 进场→立项→交付→放大 四阶段闭环 |
| **FDE 能力** | 7 项核心能力 + 4 大技术底座 |
| **FDE 资产** | 4 类可回流资产 + 明确红线 |
| **FDE 边界** | 4 个判断问题，高价值/高复杂/强合规场景 |
| **FDE 成功** | 客户价值扩张 + 产品杠杆提升 |
| **共享能力** | 共用 AI 平台 / Agent / 工具等通过 provider-neutral 契约，以本地实现、API、插件、MCP/连接器或 Agent Endpoint 可插拔接入；能力可用不等于已授权 |
| **Skill 接入** | Skill 必须契约可接入，但只有跨进程、跨项目、共享平台或独立部署有明确收益时才 API 化/插件化；本地 Skill 不强制网络化 |
