## 第一部分：Skill 标准原则

### 1.1 标准化现状与差异

#### Skill 模板

- **元数据（YAML Frontmatter）**：已形成行业事实标准。`name`（唯一标识）、`description`（触发条件+适用场景）是所有主流框架的必填项，决定了 Agent 是否加载该 Skill。
- **执行正文（Markdown Body）**：各框架存在差异。例如阿里云百炼的 description 强调"触发条件+适用场景+不适用场景"，而 Claude Code 更侧重"Use when..."的语义匹配；正文中步骤拆解粒度、是否要求 Mermaid 流程图等细节也因框架而异。

#### Agent 模板

- **无统一标准**，但有两种主流实践：
  - **角色驱动型**（如"九基石 Agent 架构法"）：YAML 元数据 + 角色定义 + 九大核心版块（身份记忆、核心任务、工具集、行为协议等），适合构建人格化、对话型 Agent。
  - **项目上下文型**（如 AGENTS.md）：由 OpenAI、Anthropic、Google 等联合推动，已有超 6 万个开源项目采用，被 GitHub Copilot、Cursor、Gemini 等主流工具支持，侧重为 AI 编码代理提供项目级上下文。

### 1.2 SKILL.md 标准模板

```markdown
---
name: skill-identifier          # 必填，kebab-case，≤64字符，必须与目录名一致
description: "Use when... [触发场景] + [核心功能] + [不适用场景]"  # 必填，≤1024字符
version: 1.0.0                   # 可选，语义化版本
license: MIT                     # 可选
compatibility: "Python >= 3.10"  # 可选
allowed-tools: [Bash, Read]      # 可选，预授权工具列表
---

# [Skill 名称]

## 概述
- **核心功能**：一句话说明做什么
- **适用场景**：列表说明何时使用
- **不适用场景**：明确排除的情况

## 执行步骤
1. **步骤一**：[原子化操作，使用命令式动词]
   - 子步骤/条件分支
   - on_error: [重试/降级/转人工]
2. **步骤二**：...

## 输入输出规范
| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| param1 | string | 是 | - | 参数描述 |

**输出格式**：[JSON Schema 或明确的结构化描述]

## 示例
**输入**：用户指令示例
**输出**：期望的标准输出

## 边界与约束
- 禁止事项 1
- 禁止事项 2
```

### 1.3 7 大核心设计原则

1. **专注模糊逻辑**：Skill 只处理决策、判断、理解等模糊逻辑；确定性操作（文件读写、计算）交给 `scripts/` 脚本或 MCP 工具。
2. **渐进式披露**：L1 元数据常驻（<100 tokens），L2 正文触发加载（<5k tokens），L3 资源按需引用。
3. **明确触发描述**：`description` = 能力定义 + 触发场景/关键词，显式包含高频词便于向量检索匹配。
4. **指令绝对性**：消灭"你应该""我建议"等模糊语气，使用命令式动词（扫描...、提取...、格式化为...），示例驱动。
5. **清晰定义边界**：必须写明否定约束（"严禁..."）、失败路径（找不到字段返回什么错误码）、安全阈值（高风险操作需确认）。
6. **工程化闭环**：维护 `tests/` 目录，包含正例、反例、边缘案例，每次更新后自动回归验证。
7. **最小够用**：剔除常识，只写模型不知道的（内部规范、特殊 API），冗余信息稀释权重。

### 1.3.1 共享能力接入原则

Skill 以稳定的语义能力契约对外：输入、输出、状态、错误、权限、数据分类、证据和验收可被宿主检查。需要跨进程、跨项目、共享平台或独立部署时，可通过 API、MCP/连接器、CLI、插件或 Agent Endpoint 适配；本地 Skill 不因“可 API 化”而被强制网络化。适配器必须声明版本、依赖、权限、健康检查、降级和回滚，不得把供应商专属 SDK、循环或字段写入核心语义。CLI 还必须声明结构化 stdin/stdout、退出码、超时/取消和安全凭证注入。

### 1.4 5 种标准设计模式

| 模式 | 适用场景 | 核心思路 |
|------|---------|---------|
| **Tool Wrapper** | 封装库/框架最佳实践 | `references/` 放规范文档，SKILL.md 告诉 Agent 何时加载 |
| **Generator** | 结构化内容生成 | `assets/` 放输出模板，SKILL.md 指挥 Agent 按步骤填空 |
| **Reviewer** | 代码/内容审查 | `references/` 放检查清单，换清单即可切换审查类型 |
| **Inversion** | 需求模糊的复杂场景 | 强制 Agent 先提问收集信息，确认后再执行 |
| **Pipeline** | 严格顺序流程 | 设置"硬检查点"，上一步确认后才能进入下一步 |

### 1.5 Skill 目录结构标准

```
my-skill/
├── SKILL.md              # 必需：YAML 元数据 + Markdown 指令
├── scripts/              # 可选：可执行脚本（Python/Shell）
├── references/           # 可选：API 文档、规范等长参考
├── assets/               # 可选：模板、图片等静态资源
└── tests/                # 可选：回归测试用例
```
