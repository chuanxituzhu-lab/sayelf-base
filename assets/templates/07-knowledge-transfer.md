#### 2. 日常运维操作

##### 2.1 系统启动/停止

```bash
# 启动所有服务
cd /opt/ai-system && docker-compose up -d

# 停止所有服务
docker-compose down

# 查看服务状态
docker-compose ps
```

##### 2.2 日志查看

```bash
# 查看API服务日志
docker logs -f api-gateway --tail 100

# 查看RAG服务日志
docker logs -f rag-service --tail 100

# 日志文件位置
/var/log/ai-system/
```

#### 3. 常见故障排查

##### 3.1 系统无法访问

| 现象 | 可能原因 | 排查步骤 | 解决方案 |
|------|----------|----------|----------|
| 页面404 | 服务未启动 | docker-compose ps 检查状态 | docker-compose up -d 启动服务 |
| 页面500 | 后端服务异常 | 查看API日志 | 重启API服务，检查数据库连接 |
| 响应超时 | 模型API超时 | 检查网络连接 | 检查API密钥是否过期，联系供应商 |

##### 3.2 输出质量下降

| 现象 | 可能原因 | 排查步骤 | 解决方案 |
|------|----------|----------|----------|
| 回答不准确 | 知识库未更新 | 检查向量库文档数量 | 重新导入最新文档，重建索引 |
| 回答重复 | Rerank失效 | 检查Rerank服务状态 | 重启Rerank服务 |
| 幻觉增多 | Prompt被篡改 | 检查Prompt配置 | 恢复默认Prompt，检查权限 |

##### 3.3 性能问题

| 现象 | 可能原因 | 排查步骤 | 解决方案 |
|------|----------|----------|----------|
| 响应慢 | 向量检索慢 | 检查向量库CPU/内存 | 优化索引参数，增加资源 |
| 并发低 | API限流 | 检查API配额 | 联系供应商提升配额 |
| 内存溢出 | 内存泄漏 | 监控内存使用趋势 | 重启服务，排查代码问题 |

#### 4. 配置管理

##### 4.1 关键配置文件

| 文件路径 | 用途 | 修改后需重启 |
|----------|------|--------------|
| /opt/ai-system/.env | 环境变量（API密钥等） | 是 |
| /opt/ai-system/config/prompt.yaml | Prompt配置 | 否（热加载） |
| /opt/ai-system/config/rerank.yaml | Rerank参数 | 否（热加载） |

##### 4.2 修改配置流程

1. 备份原配置文件：cp config.yaml config.yaml.bak
2. 修改配置
3. 验证配置格式：python validate_config.py
4. 重启服务（如需）：docker-compose restart <service>
